# Katkıda Bulunma

AEGIS SOC laboratuvar/geliştirme çalışmasıdır. Geliştirmeler önce kanıt, sonra değişiklik yaklaşımıyla yapılır.

1. Issue'da amaç, etkilenen modül, sürüm, test senaryosu, beklenen/gerçek sonuç ve gizli veri içerip içermediğini belirtin.
2. Her kod değişikliğini birim ve uçtan uca testle destekleyin; gerekli servis kesintisini açıkça belirtin.
3. Güvenlik açıklarını public issue ile ifşa etmeyin; [SECURITY.md](SECURITY.md) yönergesini izleyin.
4. Raw log, API key, DB, müşteri/gerçek kullanıcı verisi veya izinsiz ağ ölçümü göndermeyin.
5. Documentation değişikliklerinde **DOĞRULANDI** iddiasına test tarihi ve kaynak ekleyin.
6. Kural veya AI değerlendirmelerini kanıt ile çıkarımdan ayırın.

**Not:** Bu dosya başlangıç taslağıdır; projenin sahibi katkı ve lisans koşullarını onaylamadan genel katkıya açılmamalıdır.
